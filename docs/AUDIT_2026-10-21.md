- **Y6**：启动刷新对所有构建生效，并每 10 分钟增量刷新一次（按 mtime 差分 + 主题全量，当前规模开销小），覆盖新论坛主题。

## 4. 不做（当前版本）及重估条件

- **`/healthz` 实时探库、compose 给 app 加 healthcheck。** 现在没有任何东西消费 `/healthz`，实时探库没有读者。重估：编排里有探针指向它，即
  `grep -A4 'healthcheck' docker-compose.yml | grep -q healthz` 退出码为 0。
- **优雅停机。** `axum::serve` 由 dioxus-server 调用且没有 `with_graceful_shutdown`，要做得 fork 启动流程；回调有网关重试，下单中断时订单停在 pending 由对账关闭。重估：
  `grep -q with_graceful_shutdown ~/.cargo/registry/src/*/dioxus-server-*/src/launch.rs` 退出码为 0（上游支持后接入）。
- **对账饿死。** 滞留单按时间正序取 50 条，网关已停用的旧单会一直占位。现在只有 2 条（开发数据）。重估：
  `SELECT count(*) FROM orders WHERE status='pending' AND created_at < now() - interval '2 hours';` 大于 40。
- **列表无上限（评论、回复、标注、我的订单、管理授权列表）。** 当前每篇最多几条。重估：
  `SELECT max(c) FROM (SELECT count(*) c FROM comments GROUP BY blog_id) t;` 大于 500。
- **案例 README 图片地址改写与课程版不一致**（遇到 `)` 截断）。现有 README 没有这种地址。重估：
  `grep -E '!\[[^]]*\]\([^)]*\(' assets/cases/*/README.md` 有输出。
- **五份 frontmatter 解析。** 只在值里出现 `---` 时才会不一致，现有内容没有。重估：
  `grep -rlE '^[a-z_]+:.*---' assets --include='*.md' --include='*.mdx'` 有输出。
- **支付 SQL（`claim_paid`、`mark_refunded`、回调处理）缺数据库级测试。** 仓库没有数据库测试设施，状态机逻辑已有 MockStore 测试，H1–H3 改动做过本地端到端验证。重估：下次改这些函数的 SQL 时，先补测试设施。
- **async 里的 `std::fs`。** 文本内容共 49KB（55 个 md），没有可测影响。重估：
  `find assets \( -name '*.md' -o -name '*.mdx' -o -name '*.yaml' \) -print0 | xargs -0 cat | wc -c` 超过 5000000。

以上门已核对：命令类的门现在均为「不触发」，构造对应输入（含 `healthz` 的 healthcheck、含
`with_graceful_shutdown` 的文件、`![a](img_(1).png)`、`title: a --- b`）时均触发；两条 SQL 当前为 2 与 1。
