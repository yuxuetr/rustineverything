方法：只读审计代码 + 本地 dx（localhost:8080）实测 + `cargo audit`。已有的 SEC-01–SEC-24
（`SECURITY_REMEDIATION.md`）、S6、阶段 O 的 SEO 项不重复计入。任务见 Todos.md 阶段 H（支付与安全）、
阶段 G（SEO）。

## 1. 已确认在位的控制

- 回调验签：Stripe `Hmac::verify_slice`（常量时间）、±300s 时间窗、原始 body；微信时间窗 + 验签 + AES-GCM + appid/mchid；支付宝 RSA2 + app_id。
- 金额以库内订单快照为准（`pipeline::decide`）；价格服务端算（`Pricing::quote`）；打赏只能选固定档位。
- 认领是条件 UPDATE，并发回调只有一个生效；`out_trade_no` 唯一；权益 upsert。
- Stripe 成功 / 取消地址由服务端拼接（无开放重定向）；订单只能本人查；管理接口 `require_admin` 回库确认。
- JWT 固定 HS256 并校验 exp；会话 Cookie HttpOnly + SameSite=Lax（https 时 Secure）；OAuth state 用 OsRng。
- 用户原始 HTML 按文本显示，链接协议白名单；CSP / HSTS / frame-ancestors 已配；pay_audit 不记密钥。
- SEO：除课节页外，各页标题 / 描述 / canonical 在 SSR 里且不重复；robots、sitemap、Atom feed 在位；缺失内容多数返回 404。

## 2. 支付与安全：要修的

| # | 问题 | 证据 | 失败场景 |
| --- | --- | --- | --- |
| P1 | 已退款订单可被成功回调改回 paid | `payment/src/pipeline.rs:105` 只排除 `paid`；`:174` 只有 `paid` 走幂等快路径 | 首次回调发货失败返回 500（认领已落库）→ 管理员退款 → 网关重试成功回调 → 订单变回 paid、再发一次课 |
| P2 | 网关后台退款 / 拒付不撤销权益 | `course/src/server.rs:2102` 非 `checkout.session.*` 事件一律 200 | 作者在 Stripe 后台退款或买家拒付后，课程权限永久保留 |
| P3 | 购买会覆盖管理员授予的来源 | `server.rs:1332` 冲突时更新 `source` | 用户先有 admin_grant 又自己买了 → source 变 purchase → 退款时整行删掉，管理员授予的权限一起没了 |
| P4 | 下单接口不在严格限流桶 | `app/src/server/rate_limit.rs:134` 只有 `/api/auth/`、`/api/pay/` | 登录用户每秒 20 次下单，每次写一行订单并调用一次 Stripe |
| P5 | 应用端口直接暴露，限流键可伪造 | `docker-compose.yml:106` 发布 `8080`；`client_key` 信任 XFF 首段 | 绕过网关直连 8080，每个请求换一个 XFF 就是一个新桶（含 `/api/auth/*`） |
| P6 | 依赖漏洞 | `cargo audit`：14 个（rustls、h2、quinn-proto 等） | 升级到修复版本即可；rsa（Marvin）无修复版，仅用于支付宝 / 微信签名，风险低 |
| P7 | 视频嵌入 id 未校验 | `widgets/src/components.rs:43,62` 把 id 拼进 iframe 地址 | 评论里 `<YouTube id="x?autoplay=1&...">` 可在允许的域内注入路径和参数 |

设计：

- **P1**：`claim_paid` 改为只认领 `pending` / `closed`（`closed` 必须保留：对账 2h 关单，Stripe 付款页 24h 有效）；`decide` 对 `refunded` 返回新分支 `AckRefunded`（确认收到、不发货、记 pay_audit 告警）。
- **P2**：Stripe 处理 `charge.refunded`（仅 `refunded == true` 即全额）与 `charge.dispute.created`：按 `payment_intent` 找 `provider_txn` 相同的订单，执行与管理员退款相同的后半段（条件 `paid → refunded` + 撤销 purchase 权益）。抽出 `mark_refunded(db, order)` 供两处共用。部分退款只记日志。拒付直接按退款处理：资金已被冻结，赢了拒付由管理员手动重新授予。我方管理员退款也会触发 `charge.refunded`，条件 UPDATE 保证幂等。支付宝 / 微信的退款通知暂不接（商户号未开，无法验证），见 §4。
- **P3**：购买发货改为冲突时不更新（`do_nothing`），管理员授予仍覆盖来源。两种顺序下退款结果都正确：先赠后买 → 来源保持 admin_grant，退款不删；先买后赠 → 来源变 admin_grant，退款不删。
- **P4**：`/api/orders/create`、`/api/orders/tip` 归入严格桶。
- **P5**：compose 里应用端口只绑 `127.0.0.1`（宿主上的反代仍可访问）；DEPLOY_GUIDE 说明。
- **P7**：id 只允许 `[A-Za-z0-9_-]`，不合规不渲染 iframe。

## 4. 不做（当前版本）及重估条件

- **英文独立 URL / hreflang。** 现有 110 篇内容全部是中文，英文只是界面语言；给英文开独立 URL，收录到的也是中文正文配英文外框。只做 S2（`lang="zh-CN"`）。
  重估：出现不含汉字的内容文件，即下面命令输出非 0：
  `find assets crates/app/assets -name '*.md' | perl -ne 'chomp; open F,"<:utf8",$_; local $/; $c=<F>; print "$_\n" unless $c=~/\p{Han}/' | wc -l`
  （已反向验证：现为 0；放入一份纯英文 md 时为 1。）
- **重复付款拦截。** 同一课程开多个付款页都付掉时会重复扣款。没有观察到，且管理员可退款。
  重估：`SELECT user_id, product_ref FROM orders WHERE status='paid' AND product_kind='course' GROUP BY 1,2 HAVING count(*)>1;` 返回任意行。
- **支付宝 / 微信退款通知。** 商户号未开，无法端到端验证。重估：启动日志里支付宝或微信为「已启用」（D1）。
- **退出登录吊销 token。** 现有 `token_version` 一改就是全设备下线；要单个 token 吊销得加黑名单表。写路径已回查 `tv`，被盗 token 只能读 7 天。重估：出现「退出后会话仍可写」或需要单设备下线的需求。
- **CSRF token。** 依赖 SameSite=Lax；前提是没有攻击者可控的同站子域。重估：站点开放用户子域或第三方托管子域时。
- **错误原文返回前端、og:image。** 前者影响低（不含密钥）；后者需要作者提供 1200×630 的分享图。
